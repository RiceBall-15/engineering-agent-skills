# 多语言、多项目组策略适配

进入一个仓库或切换模块时，先读取其有效规约和配置。共享技能负责协作与验证原则，不规定公司统一技术栈、分支模型或发布制度。只收集当前任务会用到的信息；已有证据可回答的问题不再询问。

| 策略 | 优先读取的证据 | 共享技能不预设什么 |
| --- | --- | --- |
| 分支与集成 | 仓库规则、目标 PR、发布维护策略、已确认基线 | 不固定分支名；不一律要求新功能分支；不把合并或变基设为唯一方式 |
| 测试与 CI | 当前模块测试、构建脚本、CI 配置及交付要求 | 不预设测试目录、测试框架或版本控制策略；不因不同语言而降低行为覆盖 |
| 工具与运行时 | 仓库清单、锁文件、版本文件、官方适配能力 | 不自动安装索引或插件；不统一包管理器、运行时版本或模型 |
| 编码与接口 | 适用规则、格式化器、邻近有效实现、公共契约 | 不预设注释语言、HTTP 方法、分层方式或每函数文档模板 |
| 需求与设计 | 已确认 Issue、需求、接口规范、设计决定、错误复现 | 不要求所有团队都有 PRD、UI 原型或相同文档目录 |
| 验证环境与发布 | 隔离资源、项目环境说明、门禁、授权范围 | 不预设某种数据库、容器、部署平台；不以本地成功代表上线 |
| 协作与权限 | 宿主能力、任务授权、模块所有权 | 不强制使用多 agent、worktree 或某个特定工具 |

## 最小适配记录

仅在多轮任务或策略可能混淆时，将以下几行写入已有任务记录：

```text
适用范围：仓库 / 模块
策略来源：规则或配置位置、当前确认
分支与基线：本任务采用的方式和实际 ref/SHA
验证与交付：相关入口、CI 门禁、提交范围
例外：明确授权的例外及失效条件；无则不填
```

一个 monorepo 也可能包含不同语言和工具链。根规则适用于全仓，模块规则只适用于其范围；不要用后端构建命令验证前端，也不要将库项目的版本策略套到独立服务。索引对当前语言不支持时，使用实际可用的结构工具或阅读方式，不编造索引结果。

## 通用规则、默认值与个人约定

- **通用规则**：不猜关键需求和写入归属；不混入无关改动；验收与证据对应；不冒充完成或越过权限。这些不依赖语言。
- **可覆盖默认值**：缺少既有规范时提出的建议，必须标明只是起点。例如有意义的提交标题格式；不能把建议说成公司已批准的强制规定。
- **团队策略**：适用于明确的仓库/模块，来自项目规约或负责人确认；遇跨团队任务分别记录。
- **个人约定**：来自使用者，作用范围需明确；只在个人记忆/本地偏好中保存，不复制进共享规则、安装示例或公司发布包。范围不明时不能自动跨项目应用。

更新或打包时采用已审核的共享文件清单，排除个人偏好、任务日志、真实仓库绑定、环境配置与凭据。示例应标明是假设或公开来源，不能把作者项目的特殊策略改名后仍作为通用禁令。
