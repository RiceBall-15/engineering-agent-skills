# Excalidraw 工程绘图 Skill

版本：1.3；日期：2026-10-15。

面向编程与技术沟通的绘图技能：根据需求、设计文档或代码绘制架构、流程、调用链、时序、状态、数据流、部署及迁移对比图。每次图稿作为独立文件夹交付，保留可编辑源文件、实际预览和维护说明。

## 绘图采用哪些规范

架构图默认按 C4 选择上下文、容器、组件或部署视图；技术流程、时序和状态图默认使用 UML 2.5.1 的对应常用子集。明确需要 BPMN 时采用 BPMN 2.0.2 常用子集。用户或项目已有记法时说明差异，不能混用符号后继续宣称符合某个标准。

- **画之前**：确定用途、范围、现状/目标状态与图种；读取该图种的规范。
- **画的时候**：检查层级、节点字段、边界、关系标签、分支与箭头语义；按排版约定设置字号和间距。
- **交付之前**：执行审图清单，在成果 README 记录规则编号、结果和依据；错误未修复或必要验证未执行时标为草稿。

来源见 [规范来源与约束性质](references/standards-sources.md)。C4 是架构表达方法，UML/BPMN 是正式规范；配色、间距、文件组织等是本技能的团队约定，不冒称行业强制规定。这些是 agent 执行规则，不是自动保证所有图合规的检查软件。

## 风格可以选择

首次绘图且没有偏好时，agent 会提示选择 **手绘、简洁工程、白板草图**；已选择后沿用，不每次重复询问。已有图稿默认保持原风格；用户可随时说“切换成手绘”或“这张改为规整线条”。三种预设是本技能对 Excalidraw 属性的组合，不是官方固定主题。

个人长期偏好可保存到宿主记忆或安装目录的 `preferences.local.md`，升级时保留、共享包中排除。分享给同事时不会强加作者的个人选择。详细规则及官方能力依据见 [风格选择与预设](references/style-presets.md)。

## 先准备运行环境

Skill 是绘图规则，Excalidraw 是编辑/导出工具，两者需要分别准备。网页版可以直接使用，无需安装桌面应用；希望 agent 自动生成预览时，建议配置官方 CLI。不要把“Skill 已安装”当作“导出环境已可用”。

详细步骤见 [安装与首次验收](references/setup.md)，包括：

1. 放置本技能并确认 agent 已加载。
2. 选择网页版手动导出，或安装官方 CLI 本地自动导出。
3. 用简单中文流程图检查可编辑源文件、PNG 和中文显示。

**最省事的方式：把技能压缩包与下面这段话一起发给自己的 agent。**

```text
请根据附件中的 excalidraw-engineering/README.md 和 references/setup.md，帮我安装并验证这个绘图技能。

先检查当前工具的技能目录、Node.js/npm、可用浏览器和已有 Excalidraw 工具，已有能力直接复用。
我授权你在用户级或独立工具目录安装此技能及必要的官方 Excalidraw CLI；不要往业务项目添加依赖或覆盖同名旧文件。
缺少 Node.js 或浏览器时，优先使用已有用户级安装方式；需要管理员权限、改变系统默认版本或宿主不支持安装时再说明具体问题。
仅做本地生成和导出，不登录、购买订阅、上传图稿或创建云端分享。

安装后按 UML 活动图常用子集生成一张“接收请求→校验→成功/失败”的中文示例图，标清判断出口条件和终点含义，在独立 diagrams/<实际日期>-setup-check/ 文件夹保存 .excalidraw、PNG 和 README。
运行真实导出并查看图片，按 references/review-checklist.md 记录语义和视觉检查结果。报告技能路径、工具版本、输出文件和实际验证结果；有缺口就说明，不能只看到安装成功便宣布全部可用。
验证通过后，按这个技能处理我后续提供的架构图或流程图需求。
```

这段指令授权接收它的 agent 执行安装与验收；安装仍须遵守其宿主权限。如果只提供了本说明文件、没有发送这段指令，不视为已经授权修改环境。

## 开始绘图

将整个 `excalidraw-engineering` 目录放入工具支持的技能目录，保留相对路径。Codex 可使用配置的用户技能目录，通常为 `$CODEX_HOME/skills`，未设置时为 `~/.codex/skills`。其他工具按其实际加载方式接入；`agents/openai.yaml` 是可选的 Codex 展示信息。

示例请求：

```text
请使用 $excalidraw-engineering，根据当前项目的订单处理代码，画系统总览和订单创建流程。
图要供开发评审使用，明确实际调用、事务边界和失败分支。
将成果保存到独立文件夹，包含可编辑源文件、预览和说明。
```

```text
请使用 $excalidraw-engineering，把这份设计方案画成架构图和关键时序图。
标明这是目标方案，将尚未确认的关系标出来，不要描述成已经上线。
```

```text
请使用 $excalidraw-engineering，修改这个已有成果目录中的流程图，增加取消分支。
保留原版本，生成 v02 源文件和对应预览，并更新说明。
```

只说明问题和材料即可，图种与布局可由 agent 根据用途选择。涉及现状/方案、范围和关系真实性的歧义才询问。

## 独立成果目录

项目内默认使用 `docs/diagrams/<YYYYMMDD>-<topic>/`；无项目时放在当前可写工作区的 `diagrams/` 下。用户指定路径优先。

```text
docs/diagrams/20261014-order-processing/
├── README.md
├── 01-architecture-v01.excalidraw
├── 01-architecture-v01.png
├── 02-flow-v01.excalidraw
└── 02-flow-v01.svg
```

日期和主题按任务填写，不固定为上例。新任务同名时追加目录序号；修改旧图时新增版本，默认保留原文件。单图只生成必要文件，不强制凑齐图种。成果目录与技能安装目录分开。

## 工具与成本

技能本身是文本规则，不捆绑 Excalidraw 应用、浏览器、渲染器或网络服务。优先复用已可用工具；新环境按安装指南配置官方 CLI，或使用网页版手动导入和导出。已有 `excalidraw-diagram` 技能时也可复用其渲染能力，不要求必须安装它。

本包参考了现有 Excalidraw 技能的元素绑定和渲染检查思路，并针对工程沟通重新组织规则；不要求所有图塞入代码片段、固定容器比例或为了视觉变化使用不同形状。

使用成本来自模型、代码分析和实际导出工具。渲染器可能需要浏览器、字体或网络依赖，以环境为准。未实际导出、未查看预览时必须报告验证缺口；不能用文件存在冒充绘图验收完成。

## 本版验证范围

已检查主技能格式、包内引用和压缩包完整性，并进行以下文档级场景走查：

| 场景 | 应有行为 |
| --- | --- |
| 代码与旧设计矛盾 | 区分现状与目标，按用途取证，标注冲突 |
| 调用关系不确定 | 核查源码或显式标记待确认，不虚构连接 |
| 新任务目录同名 | 新增目录序号，不覆盖已有成果 |
| 用户修改旧图 | 保留源图，新增版本并同步导出 |
| 中文字体未加载 | 查看实际预览，修正或说明阻塞 |
| 只有 JSON 解析成功 | 不宣称已导入、已渲染或已视觉验证 |
| 源图修改但预览还是旧版 | 重新导出受影响文件 |
| 图面太密 | 分总览与必要细节，不无限缩字 |
| C2 混入私有方法和 Pod 实例 | 按主体层级重排，必要时拆组件或部署图 |
| UML 时序图用虚线表示异步 | 改为实线开放箭头，回复按独立记法绘制 |
| 条件分支被画为并行汇合 | 依据真实执行语义改为合并节点 |
| BPMN 顺序流跨 Pool | 改为各参与者内部顺序流与跨 Pool 消息流 |
| 只写“符合规范”，未列检查依据 | 补规则编号、实际结果、节点/边/预览依据 |
| 内部架构需要公开网站导出 | 核对授权，优先本地处理，不自行上传 |
| 用户只要求绘图 | 不顺手修改代码、提交或发布 |

本轮检查了技能格式、文件引用、打包完整性与文档规则；v1.3 配套的四张示例实际导出了 SVG/PNG，并进行了中文显示及目视检查。示例验证不等于独立模型行为评测，也不能保证其他运行环境的字体和导出兼容性。

配套示例存放于 GitHub 仓库的 [examples/excalidraw-engineering](https://github.com/RiceBall-15/engineering-agent-skills/tree/main/examples/excalidraw-engineering) 目录，含风格对照、Online Boutique 购物车架构与加购时序、原创 CI 活动图，以及 `index.html` 展厅和来源说明。不要求将示例放入技能安装目录。
