# 风格选择与个人偏好

核对日期：2026-10-15。Excalidraw 可组合线条粗糙度、填充、字体、颜色和圆角；以下三种是本技能提供的便捷预设，不是官方固定主题。风格控制外观，C4/UML/BPMN 控制含义，两者独立。

## 什么时候提示用户

优先级：本次明确要求 → 修改已有图时保留原风格 → 已有项目约定/个人偏好 → 首次提示选择。

- 用户已说“我偏向手绘”，直接采用手绘，不重复询问。不将个人喜好写成全公司强制要求。
- 对没有偏好的新用户，在首次绘图开始时提供一次简短选择，可附现成风格对照图。支持异步提问时，先询问，同时继续取证和整理图模型；不让配色选择阻塞代码分析。
- 示例提示：“这次图稿想用哪种外观？① 手绘：轻微笔触、适合分享；② 简洁工程：规整线条、适合评审；③ 白板草图：更随性、适合讨论。也可以沿用现有图的风格。”
- 非必须的偏好问题给用户合理回复时间（例如约 60 秒）；用户没选且未要求必须等待时，明确说明先采用轻手绘默认值。时间经过不代表用户授权安装或其他操作。
- 没有交互提问能力或用户要求直接完成时，用已知偏好；无偏好则告知采用轻手绘默认值并继续，不为低风险风格问题停工。
- 用户选择后，在本会话和本次成果 README 记录；需要跨会话沿用时用宿主的个人记忆或技能目录可选的 `preferences.local.md`。不存在则不创建虚构偏好；写入仍须符合宿主权限。共享打包排除此文件，升级时保留。
- 若后来用户改选，更新源文件并重新导出；保持节点身份和工程语义，不另起一套内容不同的对比图。

## 三种预设

| 预设 | 默认线条 | 填充 | 字体与适用场景 |
| --- | --- | --- | --- |
| 手绘（无偏好时的起点） | `roughness: 1`，线宽约 2 | 浅色 `hachure`，密集节点可用 `solid` | 支持时用 Excalifont；中文须检查字体回退。适合架构讲解和分享 |
| 简洁工程 | `roughness: 0`，线宽约 2 | 浅色 `solid` | 可用的无衬线字体，适合正式评审和高密度内容 |
| 白板草图 | `roughness: 2`，线宽约 2 | 透明为主，少量 `hachure` | 可用手绘字体，适合早期讨论；不可用夸张笔触掩盖关系 |

必要时允许用户指定配色、深色背景或混合风格，不把预设当作唯一选项。字体选择必须核对当前运行时支持情况，不能随意给 JSON 写不存在的字体名。中文缺字时优先可读字体，报告回退，不声称已呈现中文手写效果。

## 风格不能破坏的约束

- UML 同步调用、异步消息、回复和 BPMN 消息流保持原记法；不可为了手绘把实心箭头全部换成开放箭头。
- 初始/终止点、并行条、很小的箭头等可局部用 `roughness: 0` 保持辨识；整体仍为手绘风格。
- 同一图中元素类别的样式一致。不要为“手绘”故意错位、增添无意义曲线或混用大量颜色。
- 填充纹理不可干扰文字，密集文字节点减淡填充或用浅色实心；图面白底与深色正文为默认。
- 颜色、圆角和笔触不表达未经图例定义的业务状态。标准语义与可读性验收对所有预设一样适用。

## 官方能力依据

[Excalidraw 常量定义](https://github.com/excalidraw/excalidraw/blob/master/packages/common/src/constants.ts) 中的 `ROUGHNESS` 定义 architect=0、artist=1、cartoonist=2，并列出字体及回退机制；[元素类型定义](https://github.com/excalidraw/excalidraw/blob/master/packages/element/src/types.ts) 列出 `roughness`、`fillStyle`、`strokeStyle`、`roundness` 等属性。填充包含 solid、hachure、cross-hatch、zigzag，实际可用项以所用版本为准。

运行时版本可能早于上述主分支；导出验证通过才能声称某种组合在当前环境可用。
