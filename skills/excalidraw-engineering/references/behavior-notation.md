# 行为图记法

使用哪个图种就执行哪一节。标题/图例声明“UML 2.5.1 活动图/时序图/状态机图（常用子集）”或“BPMN 2.0.2（常用子集）”。子集表示省略未用的高级构件，不能改变已用符号的语义；不宣称完成元模型或完整标准一致性认证。

## B1：UML 活动图，用于工程流程

**标准记法摘要**：动作是圆角矩形；初始点为实心圆，活动终点为靶心，流终点为圈内 X；判断/合并用菱形，并行分叉/汇合用粗线段。控制流用实线开放箭头，条件写在边上的方括号内。活动终点结束整个活动，流终点只结束到达它的流。

**本技能的执行约束**：

- 用动词描述动作；初始点旁说明触发。判断出口写 `[校验通过]`、`[else]` 等可判断条件，禁止无标签的“凭位置猜分支”。确定性业务选择的条件应互斥且覆盖已定义情形；若原业务允许非确定选择，说明其含义。
- 条件分支的替代路径用合并菱形汇合；实际并行执行用 fork，等待并行工作完成用 join。不能用一个判断菱形表示“同时执行”，也不能用 join 等待互斥分支全部到达。
- 区分“请求已接收”和“任务已完成”；只表达受理接口的图，范围需写清，不能把 202/入队画成任务成功。
- 核对成功、失败、取消、超时及重试等与范围相关的路径；不存在的机制不补画。持续监听可没有结束点，须说明持续运行和退出边界，不虚构终态。
- 泳道按责任主体划分，交接连线跨泳道；泳道不是系统部署节点。事务、权限、幂等约束通过相邻注释说明，不发明没有图例的新控制符号。

## B2：UML 时序图，用于参与者交互

**本技能选用的标准消息记法**：

| 对象 | 画法 |
| --- | --- |
| 生命线 | 参与者下方竖向虚线，时间向下 |
| 同步调用 | 实线 + 实心箭头 |
| 异步调用/信号 | 实线 + 开放箭头 |
| 回复 | 虚线 + 开放箭头；UML 也允许实心回复箭头，本技能固定用开放式 |
| 条件/循环/并行 | `alt` / `opt` / `loop` / `par` 组合片段，操作区条件明确 |

**本技能的执行约束**：

- 禁止“虚线=异步”的通用画法覆盖上述记法。生命线与回复虽同为虚线，但由竖向轨道和横向带箭头消息区分，图例应分别展示。
- 各参与者在顶部对齐，一条生命线一个参与者；若参与者中途创建，其头部从创建点开始。消息从发送方指向接收方，发送到接收沿时间不向上。
- 消息写动作/事件名及必要业务数据；回复写结果。同步返回、异步确认、后续业务完成是不同消息，按真实机制分别表示。
- 条件片段分隔操作区并写 `[条件]`，循环写继续/终止条件或已确认上限。仅在证据支持并发时使用 `par`；不凭画面顺序断言真实因果。
- 激活条只在需要解释执行/等待时添加；不要贯穿所有参与者暗示一直执行。不伪造不存在的回复。
- 若工具不能正确表达片段或箭头，先修正源元素/拆图；确需简化时标为“自定义交互示意”，列出差异。

## B3：UML 状态机图，用于对象生命周期

**标准记法摘要**：状态用圆角矩形；初始伪状态用实心圆；终止状态用靶心；转移标签可含 `触发事件 [守卫条件] / 效果`，各部分按语义选用。

**本技能的执行约束**：

- 每张图明确一个对象，例如“订单生命周期”；节点写稳定状态名或实际枚举，不能把“调用支付接口”当作状态，除非模型明确定义其为持续的处理中状态。
- 有触发事件就标事件；带条件的转移必须写守卫；有副作用且影响理解就写 `/效果`。完成转移可无显式事件，但应能解释其触发语义，不能机械给每条边编造事件。
- 初始转移指向实际初态；没有业务终结语义的“失败/可重试”不画靶心。核对失败恢复、取消、超时的合法边，不把期待的能力当作已有转移。
- 复合状态/并发区域/历史状态超出当前需要时不要引入；确需使用则先核对 UML 第 14 章相应条款。

## B4：BPMN，仅在适用时使用

**标准记法摘要**：事件用圆形，结束事件用粗边圆；任务用圆角矩形，网关用菱形。顺序流是实线实心箭头；消息流是虚线、起端空心圆和开放箭头。Pool 表示参与者，Lane 是责任划分；顺序流不能跨 Pool，消息流连接不同 Pool。

**本技能的执行约束**：排他网关统一显示 X，并行网关显示 +；明确出口条件和汇合策略。跨 Lane 可以用顺序流，同 Pool 内不用消息流代替控制流。不能把“消费者从队列取消息”的技术框图自动改称 BPMN。涉及边界事件、补偿、复杂网关等高级语义时先核对规范，不凭图标形似猜行为。

## 依据与适用限度

[OMG UML 2.5.1](https://www.omg.org/spec/UML/2.5.1) 及其 [正式 PDF](https://www.omg.org/spec/UML/2.5.1/PDF)：活动与控制节点见第 15 章（尤其 §15.3.4），动作见第 16 章；状态记法见 §14.2.4；消息见 §17.4.4，组合片段见第 17 章。上述流程覆盖、异常检查和工具降级要求属于本技能的工程约定。

[OMG BPMN 2.0.2](https://www.omg.org/spec/BPMN/2.0.2) 及其 [正式 PDF](https://www.omg.org/spec/BPMN/2.0.2/PDF)：基本记法见第 7 章，顺序流见 §8.4.13，Pool 与消息流见 §9.3–9.4。这里只是绘图工作子集，不能用于声称流程可被 BPMN 引擎执行。
