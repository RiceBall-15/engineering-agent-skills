# 选图与规范路由

先确定图要回答的问题，再选择一种主记法。以下是本技能的默认选型，不代表所有工程图都必须使用同一标准。用户或项目已有记法时尊重既有约定，并记录差异。简单明确的任务自行选型，不为选型反复询问。

| 主要问题 | 默认记法与范围 | 绘制前必读 |
| --- | --- | --- |
| 谁使用系统，系统与谁协作 | C4 系统上下文图 C1：一个目标系统 | [C4 架构约束](architecture-c4.md) |
| 系统由哪些应用和存储组成 | C4 容器图 C2：一个软件系统 | 同上 |
| 某个应用内的组件如何协作 | C4 组件图 C3：一个容器 | 同上 |
| 哪些实例运行在哪里 | C4 部署图：一个明确环境 | 同上 |
| 一个用例跨哪些架构元素协作 | C4 动态图：一个用例，交互编号 | 同上；需消息时序语义时改用 UML 时序图 |
| 操作有哪些分支、并行和终点 | UML 活动图子集；责任分区按需添加 | [行为图记法](behavior-notation.md) 活动图节 |
| 多方按什么顺序交互 | UML 时序图子集 | 同上，时序图节 |
| 一个对象的合法状态如何变化 | UML 状态机图子集 | 同上，状态图节 |
| 用户明确要求 BPMN 或正式跨参与者业务流程 | BPMN 2.0.2 子集 | 同上，BPMN 节；超出子集需核对官方规范 |
| 数据经过哪些处理与存储 | 自定义数据流图，显式声明记法 | 本文件数据流约定 |
| 迁移前后有什么变化 | 同一记法的前后两图；过程另用活动/时序图 | 对应图种规范 |

## 默认选择的边界

- “架构图”面向开发者且材料含应用和数据存储时，通常从 C2 开始；面向业务读者和外部协作概览时从 C1 开始。材料不足不能成为臆造 C2 的理由。范围歧义影响内容时才问。
- C3 是容器内部职责分解，不是类图。类关系需求应明确为 UML 类图，另核对对应规范，不能把 C3 盒子改成类名后声称完成。
- 每张图一个主记法；一套成果可有不同记法的多图。局部调用步骤放 UML 时序图，不往 C2 中塞判断菱形。静态结构箭头不等于执行顺序。
- 本技能只覆盖常用子集。用到未覆盖的 UML/BPMN 元素时查官方定义；工具无法表达时拆图或标为自定义示意，不能发明符号后继续声称符合标准。
- 用户指定简易流程图时可用自定义记法，但要声明动作、判断、起止和连线含义，不标为 UML/BPMN。

## 自定义数据流与迁移约定

数据流节点显式标为外部实体、处理或存储；边标数据名称及方向。调用动作和数据返回可能方向相反，分别画出；只需控制流时换活动图。此约定不宣称符合 Yourdon、Gane–Sarson 或其他完整 DFD 标准。

迁移前后保持同一抽象层级、对象名称和图例，并排标注版本/阶段及新增、变更、删除状态。共存、切换条件和恢复路径有证据才画；阶段步骤不要和静态依赖共用未说明的箭头。

所有图均须有标题、范围、现状/目标/示意状态和图例。跨图对象名称稳定；拆图时用图号引用。只生成解释问题必需的图，不强制交付完整 C4 四级图集。
