# 独立成果目录与版本

每次绘图任务的正式成果放在独立目录。下例是一组架构与调用链图，单图任务只保留对应文件：

```text
docs/diagrams/20261014-order-processing/
├── README.md
├── 01-architecture-v01.excalidraw
├── 01-architecture-v01.png
├── 02-request-flow-v01.excalidraw
└── 02-request-flow-v01.svg
```

不要在每次任务中照抄日期或主题。目录是本次成果包；技能安装目录是规则文件，二者不能混用。

## 文件规则

- 用户指定目录优先；没有项目时在可写工作区的 `diagrams/` 下创建。
- 新任务同名目录已存在时追加序号，不混入既有任务。明确修改已有图时继续同目录，用 `v02` 等版本保存源文件和同版本导出，说明文件标注当前推荐版本。
- 多图使用相同编号/主题的源文件和导出文件，便于一眼对应。单文件扩展名使用 `.excalidraw`，不能隐藏为 `.json.txt`。
- README 使用相对链接，目录整体移动后仍能打开。图片尽量嵌入源文件；如需单独素材，放本目录 `assets/` 并说明用途。
- 技术证据主要记录仓库相对路径、符号与提交标识。避免把个人绝对路径、真实凭据和无关内部信息放到共享说明。
- 原始分析笔记只有对维护必要时才保留；浏览器缓存、依赖包、日志堆积不进入成果目录。
- 用户需要打包时，将整个成果目录打包；检查解压后源文件与说明引用完整。打包技能不等于打包某次图稿。

## 说明文件

使用 [成果说明模板](../assets/diagram-readme-template.md) 填写实际内容。小图保持简短；不能保留空白占位项冒充完成记录。

每张图至少记录：图号/标题、现状/目标/示意状态、范围、采用规范/层级、源文件、实际导出、证据、图例和验证状态。依照 [审图清单](review-checklist.md) 记录适用规则、结果与依据；自定义记法或标准偏离须明确说明。源码依据包含提交/分支；若依据未提交改动，说明相应文件和读取时状态，不能声称代表某个干净提交。

证据不足的关系注明“待确认”及其影响，别仅把疑问藏在说明底部，图面同时标出。通用示意可使用虚构示例，但必须写明“示例，不代表项目当前架构”。

## 最终回复示例

```text
已绘制系统总览和请求处理流程，区分了同步调用、异步事件及异常终态。

成果目录：实际目录链接
可编辑源文件：实际 .excalidraw 链接
预览：实际 PNG/SVG 链接或内嵌图片
说明：README 链接

验证：说明实际完成的结构检查、导出和目视检查；列出重要待确认项。
```

只有实际完成的步骤才写“已”。用户只要求绘图时，不顺手修改源代码、提交/推送、发布或分享给其他人。
