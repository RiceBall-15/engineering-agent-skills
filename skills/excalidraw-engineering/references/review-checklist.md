# 交付前审图清单

每次绘图必须执行。先审语义，再审布局，最后核对实际源文件和导出；无需为简图另建报告，结果写入成果 README。规则是人工/agent 审查要求，不是已内置的自动检测器。

## 如何记录

每项使用“通过 / 失败 / 未验证 / 不适用”，附具体节点、边、文件或检查依据。不适用须写原因，例如“本图为 C2，B2 时序规则不适用”。同类规则可一行合并，但不能掩盖失败项。没有实际查看图像，V1–V3 必须写未验证。

| 编号 | 适用范围 | 通过条件 |
| --- | --- | --- |
| S1 | 全部 | 图头有主题、图种/层级、范围及现状/目标/示意状态；README 声明记法 |
| S2 | 全部 | 关键节点和关系有依据；未知明确标注；未把假设画成现状 |
| S3 | 全部 | 图例解释所用符号/边界/线型，跨图命名一致；偏离标准已明示；外观符合已选风格/偏好 |
| A1 | C4 | 主体分解层级正确，外部支撑元素有类型/边界；部署图有环境，动态图有用例/编号 |
| A2 | C4 | 名称、类型、职责齐全；容器/组件技术明确或待确认；边界有名称 |
| A3 | C4 | 有向关系标动作；跨进程容器关系标协议/机制；调用与数据方向不混淆 |
| B1 | 活动图 | 起止含义正确，条件出口可判断；条件合并与并行汇合不混淆；相关失败路径完整 |
| B2 | 时序图 | 同步/异步/回复箭头正确，时间和消息方向正确；必要片段/条件清楚 |
| B3 | 状态图 | 一个对象的状态与动作分开；初始、终止、触发/守卫和恢复路径符合实际 |
| B4 | BPMN | 事件/任务/网关正确；顺序流不跨 Pool，消息流跨参与者；汇合策略正确 |
| D1 | 自定义/数据流/迁移 | 记法明确且未冒称标准；数据和控制关系可区分；前后对比层级一致 |

| V2 | 全部 | 连线不穿无关节点/文字，箭头落点明确，标签对应唯一连线；交叉不误示汇合 |
| V3 | 全部 | 阅读方向、对齐和层级清楚；依照排版约定，偏离有理由；不靠缩小正文塞内容 |
| F1 | 全部 | JSON/ID/绑定/素材检查通过，源文件经实际打开或渲染，核心元素保持可编辑 |

## 处理失败

1. 语义错误先修源文件，再重新检查与导出；不能只在 README 解释一个仍然画错的箭头。
2. 缺关键证据影响整体结论时保留草稿，并指出具体待确认关系；少量明确标注、不会使结论失真的未知技术字段可作为已知限制，不等于伪造事实。
3. 版式默认参数可因品牌/版面调整，但不可豁免文字可读、箭头可辨和语义一致。用户明确选择自定义记法时更新图头和图例，不继续宣称标准符合性。
4. 无法打开/渲染、无法目视检查或源图与预览不一致时，不能宣称完整交付。清楚区分已交付文件、失败项和待验证项。

## 防退化样例（用于文档审查与后续试用）

| 输入/错误样例 | 必须采取的行为 | 对应规则 |
| --- | --- | --- |
| “画架构图”，素材混含服务、方法和 Pod | 按用途选 C1/C2/C3；方法/部署细节分图，关键范围不明才问 | S1/A1 |
| C2 的支付系统位于边界外 | 作为外部支撑保留且标类型，不机械删除所有异层级元素 | A1/A2 |
| UML 图虚线箭头标“异步发布” | 改为实线开放箭头；回复保留虚线，更新图例 | B2 |
| 两条互斥分支进入并行 join | 改用条件合并；不引入等待永远不会到达的分支 | B1 |
| 持续运行的消费者没有终点 | 说明持续运行和退出范围，不强加成功靶心 | B1 |
| 状态“失败”还可重试，却画终止符号 | 改为普通状态并保留有据可查的恢复转移 | B3 |
| 顺序流跨 BPMN 两个 Pool | 重建参与者内流程，用跨 Pool 消息流表达通信 | B4 |
| 图内容正确但标签压线、中文截断 | 调整源文件布局，重新导出并目视检查 | V1/V2 |
| JSON 有效但没打开或看预览 | 报告结构验证，其他写未验证，不宣称验收通过 | F1/V1 |

这些是预期行为样例，不能据此声称已运行模型评测或真实渲染测试。
