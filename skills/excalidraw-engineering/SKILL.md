# Excalidraw 工程绘图

让读者看清系统由什么组成、如何协作、流程如何推进和哪里会失败。以技术语义正确、图面可读、源文件可编辑及成果可追溯为完成标准。

## 1. 适用边界

- 遵守宿主权限、用户当前要求和项目规约；本技能不授权修改业务代码、安装全局依赖、上传内部资料或发布图稿。
- 图形工具默认 Excalidraw。不得用一张图片嵌入画布来冒充可编辑工程图，也不把 Mermaid 文本改后缀当作 `.excalidraw` 文件。
- 本技能负责工程绘图，不因产品名、框架名或“工作流”等词调用外部业务操作技能。
- 已有合适的 Excalidraw 工具、集成或渲染器时复用；不存在时仍可生成标准源文件，再选择可用编辑器验证。不能假称工具已安装或已渲染。
- 可以与开发生命周期技能配合，但不强制安装或加载其他技能。绘图本身不应启动无关开发流程。

## 2. 绘图前先确定六件事

从请求和已有上下文补齐下列信息，关键语义歧义才问；外观风格按本节规则提示一次，具体颜色和一般排版自行判断：

1. **用途与读者**：评审、排障、交接、方案沟通还是分享；读者需要系统概览还是具体实现。
2. **图的状态**：当前实现、目标方案、迁移前后对比或通用示意。现状与设计不能混成一张无标注的“事实图”。
3. **范围与粒度**：涉及哪些系统/模块/入口/用例；一张图只回答一个主要问题。
4. **事实依据**：指定需求/原型/设计版本、仓库与分支、源码、已有图稿；哪些关系仍待确认。
5. **成果位置**：用户指定目录优先；未指定时按第 4 节建立独立文件夹。
6. **表达规范**：先读取 [选图与规范路由](references/diagram-patterns.md)，选定 C4 层级、UML 子集或其他明确记法，并读取对应规范文件。图面注明图种/层级，README 记录所用规范与偏离项；不能画完后再贴上标准名称。

只在会影响语义时暂停相关绘制，例如：画现状还是目标方案不明、入口有多个且无法定位、持久化边界冲突、异步流程的终态或权限职责不明。其余可用明确的假设继续，并在图和说明中标注。

对简单且明确的图，直接执行；复杂图先用简短文字说明选用图种、范围与主要关系，不要求用户批准每个坐标。

**风格提示**：首次为没有偏好的用户绘图时，按 [风格选择](references/style-presets.md) 提供“手绘 / 简洁工程 / 白板草图”一次性选择，同时继续取证。已有明确选择或个人偏好则直接沿用；修改旧图优先保留其风格。本技能目录若存在 `preferences.local.md`，读取其中个人偏好，不把该文件复制到共享包。无回复且无需等待时，说明采用轻手绘默认值并继续。

## 3. 用证据形成图模型

先列节点和关系，再布局；不要先画好漂亮的框再猜系统如何工作。

- 源码任务先确认仓库路径、分支/提交和与图有关的未提交改动；只读分析不自行切换共享目录分支。需要从特定分支取证时使用可用只读方式或对应 worktree。
- 有有效 CodeGraph 时，结构问题优先用聚焦上下文与批量源码读取；入口到出口的流转优先完整 trace，再读取关键实现。文本、配置内容才用原生搜索；索引不可用时回退并说明，不让绘图变成安装索引任务。
- 当前代码、已确认设计和用户描述是不同证据。发现冲突先标出，不把未实现设计画成线上现状。
- 只核查决定画面含义的实现、协议和配置；公共协议/框架行为不确定时查官方资料，内部实现以实际代码为准。不得为画图将内部源码发往公共搜索服务。
- 真实关系需要真实名称和含义；未知连接标记“待确认”，不要虚构接口、消息名、数据库、重试、缓存或分布式机制。
- 概览图可用业务名称，细节图保留必要的入口、事件或状态名。证据索引放说明文件，不强制把整段代码和 JSON 塞进图面。

在说明文件记录最小图模型：节点的名称/职责/边界；关系的源/目标/方向/含义；分支条件或状态迁移；关键证据与未确认项。若一个节点只是为了排版，不将其当作实际组件。

架构图必须应用 [C4 架构约束](references/architecture-c4.md)；流程、时序和状态图必须应用 [行为图记法](references/behavior-notation.md) 中对应小节。无需加载不相关的图种。已有项目标准或用户指定记法优先，但必须明确其名称、符号和差异，不把自定义图宣称为标准图。

## 4. 成果必须放到独立文件夹

默认路径：项目内 `docs/diagrams/<YYYYMMDD>-<topic>/`；无项目时在当前可写工作区建立 `diagrams/<YYYYMMDD>-<topic>/`。使用用户所在时区的日期，主题名称简短可识别。

- 用户明确指定位置时遵从；无写权限则使用允许的输出目录并说明，不偷偷写到别处再声称成功。
- 新任务碰到同名目录时使用 `-02`、`-03` 等后缀，不能覆盖旧成果。明确修改既有图时，在原成果目录保存新的 `v02` 源文件和同名导出，原版本保留；用户明确允许原位覆盖时例外。
- 所有正式源文件、导出图、必要本地素材和说明位于该目录内。缓存、下载依赖和临时构建放临时区域，交付时不混入。
- 多张关联图放同一次成果目录，用编号与主题命名。只画必要图，不为凑套件自动生成所有图种。

示例目录见 [成果交付约定](references/delivery.md)。最低完整成果为：

- `01-<topic>-v01.excalidraw`：可编辑源文件。
- `01-<topic>-v01.png` 或 `.svg`：从该版本源文件实际导出的预览，至少一种。
- `README.md`：用途、状态、范围、图例、依据、未确认项、文件列表和验证状态。

若实际未能导出或目视检查，只能交付“源文件草稿/待视觉验证”，不能伪造导出、创建空文件占位或宣称完整完成。

## 5. 布局与视觉编码

- 架构层级、泳道或边界由真实职责决定。相同职责使用一致样式，不为了装饰强制每组使用不同图形。
- 流程通常从左到右或从上到下；方向一旦确定保持稳定。主路径突出，异常/补偿放侧边，不与主路径混在一起。
- 每条有方向的关系画箭头并按需标注动作/数据/事件；归属、分组、继承等静态关系不强行画成时间流。
- 箭头不能穿过无关节点；交叉密集时调整分层或拆图，不靠无限放大画布解决。
- 判断节点标明问题，出口标明条件；状态图的边标事件/条件，不把页面、动作、状态混为一种节点。
- 不只用颜色区分语义，同时用文字、线型或边界标签。同种关系的编码保持一致；完整符号需结合方向、箭头和位置解释，例如时序生命线与回复均可用虚线，不能仅凭虚实判断含义。
- 按已选择的风格应用笔触、填充和字体，默认白色背景、深色文字、适量留白。标题约 28–32，节点约 18–22，注释约 14–16；以实际导出可读性调整，不通过缩小正文塞内容。
- 默认中文说明，类名、接口、表名等保留原名。检查中文字体及中英文混排；长名称分行，不省略关键业务含义。
- 单图出现多个阅读主题、节点过密或正常阅读尺寸难以辨识时，拆成“总览 + 必要细节”，用图号互相引用。

按 [格式与导出](references/format-and-export.md) 的团队排版约定设置字号、间距、标签和连接点。配色属于团队约定；UML/BPMN 的线型和符号语义不得被通用配色或手绘风格覆盖。

## 6. 生成、编辑与校验

首次使用、用户要求安装或当前缺少编辑/导出能力时，先读取 [安装与首次验收](references/setup.md)。有明确安装授权时按其范围完成配置和示例验证；只有绘图授权时先复用现有工具，缺少环境再说明具体需要。不要把读取安装说明本身当作安装授权。

1. **先检查环境**：查看可用 Excalidraw 工具/本地编辑器/渲染器及其说明，确认输入输出和依赖；不凭猜测调用 API。
2. **生成源文件**：优先使用工具支持的元素生成/序列化能力；直接写 JSON 时使用已核对的元素格式，确保可独立打开。复杂图按逻辑分区构建，最后补跨区关系。
3. **编辑既有图**：先读源文件及可用预览，保留无关元素、稳定 ID、绑定和外部素材；不要未经要求重绘整张图。
4. **结构校验**：解析 JSON，检查元素 ID 唯一、坐标有效、文字/连线绑定存在、被引用图片完整。不能把 JSON 可解析等同于 Excalidraw 可用。
   同时执行 [审图清单](references/review-checklist.md) 中适用的语义规则；结构解析不能替代架构层级、条件、消息和状态语义审查。
5. **实际打开或渲染**：通过可用编辑器或渲染器导出；检查中文字体加载与画布边界。
6. **目视检查**：查看整体和细节，核对文字、箭头、标签、分组、图例、空白、裁切，以及需求要求的关键路径。
7. **修正再导出**：修改源文件后重新生成受影响预览；不得只修图片导致源图不一致。达到要求即可停止，不为了装饰反复迭代。

出现导出失败时先定位原因。连续两次同类失败且没有新证据时停止盲试，检查依赖/版本/字体/网络与可用替代方式；继续保留源文件和说明。若需用户选择安装依赖或更换工具，说明具体缺口。

## 7. 完成门槛与交付

必须按 [审图清单](references/review-checklist.md) 执行适用规则，在成果 README 留下规则编号、通过/失败/未验证/不适用和具体依据。不能只写“符合规范”。下列要求均满足才交付完整成果：

- 图种、范围、现状/方案状态与用户意图一致；关键关系有依据，未知项显式标注。
- 架构边界、调用方向、分支条件、异常和终态没有被画错或省略到误导读者。
- `.excalidraw` 可被实际工具打开或渲染，核心元素保持可编辑；不存在悬空绑定或丢失素材。
- 导出与源文件同版本，中文可读，无明显重叠、裁切、错误箭头落点或含义不明的线条。
- 文件都在本次独立成果目录；README 清楚记录验证结果和限制。

语义错误、必要标签缺失、明显遮挡或无法确认预览与源文件一致时，修正并重新验证。受环境或关键证据限制无法修正时，只交付明确标注的草稿及缺口，不用“整体美观”抵消失败项。规范依据与团队约定的区别见 [规范来源](references/standards-sources.md)。

最终简述图解释了什么，提供成果目录、源文件、预览与说明的可点击链接；有图片显示能力时展示实际预览。区分“结构检查通过”“导出成功”“已目视检查”，未验证不得写已通过。除非已获授权，不顺手提交 Git、上传云盘或创建外部分享链接。
